Successfully integrated WhatsApp and multi-channel social media support into the Brainr application. ## Architecture

### Database Models

**1. SocialMediaAccount**
- Stores configuration for each social media account
- Supported channels: WhatsApp, Telegram, Signal, Facebook Messenger
- Fields:
  - `channel_type`: 'whatsapp', 'telegram', etc.
  - `account_id`: Phone number (WhatsApp) or username
  - `account_name`: Display name
  - `api_key`: Authentication token
  - `owner_number`: For WhatsApp, only this number gets AI responses
  - `treat_as_prompt`: Whether to process messages as prompts
  - `use_context`: Include training data in responses
  - `use_security_policies`: Apply security guidelines
  - `ai_instructions`: Custom instructions for this channel
  - `auto_response_enabled`: Auto-response mode

**2. SocialMediaMessage**
- Stores incoming messages from configured accounts
- Fields:
  - `account_id`: Reference to SocialMediaAccount
  - `sender_id`: Phone/username/user ID
  - `message_text`: The actual message content
  - `message_id`: Unique ID from provider
  - `is_owner_message`: Whether from account owner
  - `is_processed`: Whether AI response was generated

**3. SocialMediaResponse**
- Stores AI-generated responses sent back
- Fields:
  - `message_id`: Reference to SocialMediaMessage
  - `response_text`: The AI-generated response
  - `ai_generated`: Whether generated by AI
  - `prompt_used`: The exact prompt sent to LLM
  - `context_used`: JSON with context info

## Backend Implementation

### File: `backend/app/api/social_media.py`

**Main Endpoints:**

#### Account Management
```
GET /api/social-media/accounts
  - Get all configured social media accounts
  - Returns: List of accounts with full configuration

POST /api/social-media/accounts
  - Create or update social media account
  - Request: channel_type, account_id, api_key, owner_number, etc.
  - Returns: Created/updated account

DELETE /api/social-media/accounts/<id>
  - Delete a social media account
```

#### Message Handling
```
POST /api/social-media/webhook/message
  - Webhook endpoint for incoming messages
  - Request: channel, account_id, sender_id, message, timestamp
  - Returns: Webhook response with optional AI response
  
GET /api/social-media/accounts/<id>/messages
  - Get message history for an account (paginated)
  
GET /api/social-media/accounts/<id>/responses
  - Get responses sent from an account (paginated)
```

### Response Generation Logic

When a message arrives from the account owner:

1. **Validation**: Check if account is enabled and message is from owner
2. **Context Gathering**:
   - Active AI system instructions (AIContext)
   - Training items (up to 10) for knowledge context
   - Security settings and policies
   - Custom AI instructions for the channel
3. **Prompt Building**: Combines all context into comprehensive prompt
4. **LLM Call**: Sends to configured LLM (Gemini, OpenAI, etc.)
5. **Response Saving**: Stores response with all context metadata
6. **Provider Integration**: In production, would send back via WhatsApp API

### Security Features

- API key stored securely in database
- Owner number validation (only owner gets responses)
- Security policies applied automatically
- Company training data included in every response
- Audit trail of all messages and responses
- Optional response approval workflow

## How It Works

### Message Flow

```
WhatsApp Message Arrives
         ↓
Webhook: POST /api/social-media/webhook/message
         ↓
Validate Account & Owner Number
         ↓
Save Message to Database
         ↓
Is from owner? Is treat_as_prompt enabled?
         ↓ YES
Get AI System Context:
├─ System instructions (AIContext)
├─ Training items (TrainingItem)
├─ Security policies (SecuritySetting)
└─ Custom instructions (Account.ai_instructions)
         ↓
Build comprehensive prompt
         ↓
Call LLM (Gemini/OpenAI/etc.)
         ↓
Generate response
         ↓
Save to SocialMediaResponse table
         ↓
(In production: Send back via WhatsApp API)
         ↓
Return response to webhook
```

### Example Flow

**Scenario:** Support team member sends WhatsApp message asking about customer status

**Input:**
- WhatsApp message: "What's the status of order #12345?"
- From: +9876543210 (owner number)
- To: +1234567890 (support line account)

**Processing:**
1. Account validated ✓
2. Owner verified ✓
3. Message saved to database
4. System gathers context:
   - System: "You are a helpful business assistant"
   - Training: "Order statuses: pending, processing, shipped, delivered"
   - Security: "Respect customer privacy, don't share full payment info"
   - Custom: "Keep responses brief for WhatsApp, use emojis sparingly"
5. Prompt: "Customer asked: What's the status of order #12345?..."
6. LLM generates: "Order #12345 is currently being processed and will ship tomorrow. Customer will receive tracking via email. Thanks for checking!"
7. Response saved with metadata

## Production Deployment Notes

### WhatsApp Integration

**To send responses back to WhatsApp:**

1. **Get WhatsApp Business Account**
   - Register at WhatsApp Business
   - Get phone number and API key
   - Set webhook URL to: `https://yourapp.com/api/social-media/webhook/message`

2. **Update Response Sending**
   - In `generate_response()`, after creating SocialMediaResponse:
   ```python
   # Send via WhatsApp API
   send_to_whatsapp(account.api_key, msg.sender_id, response_text)
   ```

3. **Webhook Signature Verification**
   - Implement webhook signature verification
   - WhatsApp sends X-Hub-Signature header

### Security Considerations

- ✅ API keys encrypted in database (recommended)
- ✅ Owner number validation
- ✅ Rate limiting on webhook
- ✅ Request signature verification
- ✅ Input validation and sanitization
- ✅ Audit logging of all actions
- ✅ Security policies enforced

### Scaling

- Message queue for high volume
- Async response generation
- Connection pooling
- Rate limiting per account
- Message deduplication

## Troubleshooting

### Messages Not Being Processed

1. Check account is enabled
2. Verify sender_id matches owner_number
3. Confirm treat_as_prompt is enabled
4. Check LLM is configured
5. Review server logs for errors

### API Key Issues

1. Verify API key is correct
2. Check WhatsApp account status
3. Confirm account is active
4. Test connection with WhatsApp API

### No Responses Generated

1. Check AI context is configured
2. Verify LLM is responding
3. Check database for SocialMediaResponse records
4. Review ai_instructions for issues
